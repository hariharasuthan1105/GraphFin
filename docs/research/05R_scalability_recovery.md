## Existing recomputation bottleneck

`InterventionEngine.generate` rebuilds a filtered transaction DataFrame, a directed weighted `DiGraph`, centrality, and the complete 19-feature matrix for each accepted omission. A Phase 3 pilot had already measured about 6.67 seconds per accepted recomputation on average over 70 accepted records at IBM 5K, with approximately 467 seconds of recomputation in total. Candidate enumeration and rejection also matter: the frozen partial file contains many rejected candidates that do not require graph recomputation.

The new bounded profile is [profile.json](../../data/results/v2/phase5r-profile-v5/profile.json), generated by `backend/scripts/profile_phase5r.py`. It used deterministic synthetic 500- and 1,500-transaction workloads with sparse and dense graph patterns, repeated edges/timestamps, and small and extreme monetary amounts. Each reported stage is a single bounded timing; these are diagnostic measurements, not a scalability law.

|---|---:|---:|---:|---:|---:|---:|
| 500 / sparse | 0.876 s | 0.775 s | 0.989 s | 1.13× | 0.312 s | 1.49 / 1.36 MB |
| 500 / dense | 0.378 s | 0.297 s | 0.340 s | 1.27× | 0.014 s | 0.51 / 0.46 MB |

In the sparse 1,500-account case, global betweenness was the dominant measured operation (about 76% of reference recomputation time). In the dense case, graph construction and feature extraction took a larger share. Transaction-frame preparation fell from about 14–52 ms to 4–7 ms after the base frame had been cached. The indexed path therefore removes repeated timestamp conversion and avoids iterating event objects to reconstruct the same frame, but the cache's base frame (about 58 KB for 500 transactions and 174 KB for 1,500) is setup cost and retained memory. Total recomputation ranged from a 5% slowdown to a 40% speedup in these single measurements. Do not extrapolate these ratios.

The profile separately records graph construction, degree and weighted-degree aggregation, NetworkX betweenness, egonet features, behavioral group-bys, temporal sorting/aggregation, candidate enumeration, frozen Isolation Forest scoring, and serialization. For the sparse 1,500 case, graph construction excluding centrality was about 14 ms, degree operations 6 ms, egonet features 30 ms, behavioral aggregation 34 ms, temporal aggregation 38 ms, candidate enumeration below 1 ms, scoring about 14 ms, and serialization about 7 ms. Thus the measured bottleneck is not assumed; it varies with graph structure and workload.

The traced-memory figures are per-call peaks in a bounded Python process; process RSS before and after each profile is recorded in the JSON. They are not OS peak working-set measurements. Serialized feature records ranged from about 5 KB to 178 KB. The real selective run produced a 1.72 MB intervention log, 1.30 MB profiles, 0.54 MB complete-population score file, and 2.48 MB evaluation JSON. No larger than 1,500-transaction profile was launched.

## Versioned exact optimization paths

`backend/app/research/interventions/optimized_recomputation.py` adds two separately versioned paths. Neither replaces the frozen Phase 3 recomputation used by the benchmark.

`indexed-history-frame-v1` converts the immutable source history into a base DataFrame once, then selects retained rows by transaction identity. Cache identity hashes the method version, dataset and historical-content checksums, cutoff and time kind, account universe, graph-construction version, sorted omitted transaction IDs, canonical feature schema, and relevant seed. Cache returns are defensive copies; foreign-history caches and invalid omission sets are rejected. The cache is in-memory and bounded; there is no persistent feature-cache reuse.

`weak-component-exact-v1` computes exact directed betweenness independently inside weakly connected components only when the graph has at most 2,000 nodes. It computes unnormalized component values and applies the global directed NetworkX normalizer (1/((n-1)(n-2))). Applying component-local normalization would change values. At more than 2,000 nodes it falls back to the existing global sampled centrality implementation, preserving its node order, sample size and seed (500 for the tested 2,001-node case, seed 42). Component recomputation was exactly equivalent on tested inputs but slower on three of the four profiling workloads and much slower on sparse 1,500 nodes; it is an optional exact route, not a recommended replacement based on current evidence.

All paths retain directed edges and the existing `DiGraph` repeated-edge aggregation (topology counts one edge; weight and transaction count aggregate parallel transactions). Intervention omissions remain transaction-level. Features are still generated by the existing FeatureService, including its rounding and 19-column order. Self-transfers remain rejected by the Phase 3 input policy. The profile exercised repeated timestamps, repeated directed edges and monetary extremes; fixture regression tests exercise disconnected components, isolated nodes, duplicate transactions, directionality, and omission families. No feature definition or sampled-centrality policy changed.

For all 19 features, the largest observed absolute deviation against reference recomputation was **0.0** in the independent fixture and all four profiled workloads, both for indexed-frame and exact-component paths. A frozen Isolation Forest check produced bit-identical score arrays when given the identical reference and optimized feature matrices. This establishes equivalence only for the tested fixtures and workloads; it does not establish scalability at IBM 5K or 50K.

## E6_BASE calibration tie diagnosis

The frozen empirical mid-CDF maps each raw held-out E4 score to the midpoint of its insertion interval in the source-training score sample. Distinct held-out scores that lie between the same adjacent source-training values can therefore map to the same finite-grid percentile. This is not evidence of a change to the detector; it is a non-strictly-monotone calibration consequence. There is no separate score clipping step in this calibration, but its finite empirical grid quantizes held-out values.

Across six splits, the frozen mapping reduced unique scores by 232–292 accounts at IBM 5K and 1,957–2,204 at the approximately 50K tier. Mean absolute rank displacement from E4 was about 0.221 positions at 5K and 0.182 at 50K; maximum displacement was 6 and 8 positions, respectively. The existing six-seed mean AP values were 0.095910 (E4) versus 0.081992 (E6_BASE) at 5K, and 0.023494 versus 0.020825 at 50K. This is descriptive on the same supplied datasets and alternate splits; it does not independently validate labels or establish a method-wide effect.

The separate exploratory `source-logistic-rank-preserving-v3` applies

\[
g(s)=\frac{1}{1+\exp(-(s-m)/a)},
\]

where (m) is the source-training median and (a=\max(\mathrm{IQR}/1.349,\;\max|s-m|/20,\;1)), all fit using source-training scores only. The implementation uses `logaddexp` for numerical stability and rejects any input where distinct finite raw scores collapse to one float64 output. Raw equal scores stay equal. The new protocol is [`phase5r_monotonic_calibration_v1.json`](configs/phase5r_monotonic_calibration_v1.json); results and a dataset-bound manifest are in `data/results/v2/phase5r-monotonic-calibration-v4/`.

This check passed strict rank preservation for all six 5K splits and three of six 50K splits. Five distinct-score collisions occurred across the other three 50K splits, so those transforms were explicitly rejected. For the nine valid splits, output ordering is identical to raw E4 by construction and observed AP/P@10 equal raw E4. This exploratory calibration is not a substitute for frozen E6_BASE, and its unit scale floor is a prespecified numerical stability choice rather than an outcome-tuned parameter.

## Frozen 250-account cohort and selective inference

The original `phase5-interventions-v1/interventions.jsonl` remains incomplete. Its exact byte hash is `1dfa2b7928fd0321efee011b68276f76b1cc50001e141a6e0e87adc1568948d0`; it contains 318 valid JSON records for 149 accounts, all counterparty-only (70 accepted, 248 rejected), and has neither a completion manifest nor an incomplete marker. All 318 omission IDs were found in eligible historical transactions. For each of the 70 accepted rows, feature vectors were finite and length 19, the stored difference equaled intervened minus baseline, baseline vectors matched the frozen feature file, and the intervention ID matched the expected Phase 3 identity. The intervened feature values were not independently recomputed, so **none of these records were used for a scored evaluation**. The fixed 250 IDs were not replaced. Their label-stratified selection remains exploratory and has one positive; it is not label-independent or confirmatory.

The separately versioned [`phase5r-selective-top5-v1.json`](configs/phase5r_selective_top5_v1.json) defines a top-five selection by frozen E4 raw score with lexical ID tie-breaking, before held-out labels are loaded. It ran all three intervention families for the selected accounts under a 900-second ceiling and scored the complete 1,500-account split-42 held-out population. The new manifest is `data/results/v2/phase5r-selective-top5-v1/manifest.json` and records dataset, label-set, feature and baseline manifest identities, configurations, seeds, score paths and artifact hashes.

The selective run completed in 212.4 seconds. It generated 14 accepted interventions and 642 rejected candidates; four of five selected accounts had accepted interventions. Nonselected accounts retained the documented E6_BASE fallback. E4 AP was 0.194545; all CREST modes and family/weighted ablations produced AP 0.194544, one retrieved positive at P@10, and identical rankings to E6_BASE. The paired AP difference versus E4 was approximately (-7.8\times10^{-7}), with the 1,000-draw fixed-class-count bootstrap interval ([-4.62\times10^{-6},0]). The held-out prevalence was 0.4% (six positives). This indicates no rank improvement in this selective probe; it is not evidence that full CREST helps or harms. The ranking is dominated by fallback scores, the candidate policy intentionally selects high-baseline-score accounts, and the results cannot be generalized to unselected accounts.

This bounded probe demonstrates the budget-aware scoring and fallback mechanics on one split. It does not satisfy the original full-population E6 acceptance criterion. Full intervention coverage, the frozen 250-account stage, cross-seed CREST comparisons, and a separate budget-matched random-omission negative control remain incomplete. Counterparty-only, temporal-only, budgeted-only, and candidate-weighted outputs exist in this selective probe, but with four eligible accounts and only one positive they are descriptive mechanics checks, not meaningful detector ablations. A placebo score-permutation control was not run.

## Statistical limitations

All metrics use identical complete held-out IDs within the selective probe and the established average-precision, precision/recall@K, paired-bootstrap and rank-stability functions. The paired bootstrap conditions on the observed number of positive and negative accounts; it does not refit the model or account for graph dependence. At only six held-out positives, and with interventions applied to four score-selected accounts, intervals are not an inferential basis for model superiority. The old 250-account cohort's one positive is still less informative. No significance claim, confidence claim beyond the defined resampling procedure, or cross-dataset claim is made.

## Remaining blockers and Phase 5 readiness

The original full-coverage E6 experiment still exceeds the available measured compute budget because every accepted omission triggers global graph-feature recomputation and sampled betweenness. The exact cache optimization is too modest and variable to change that conclusion; component-scoped centrality was slower on the sparse profile. The next research step needs a prespecified, more substantial exact local-feature update that still recomputes or rigorously updates global centrality, followed by equivalence tests on the actual IBM history. Any approximate centrality or selective protocol must remain a separate version and cannot be substituted into the frozen primary benchmark.

Phase 5's original acceptance criteria are **not satisfied**: its intervention-based primary E6 comparison, full cohort coverage, confirmatory ablations, and negative control are still missing. Phase 5R has established a reproducible feasibility demonstration and specific bottleneck evidence, but the research is not ready to claim a validated E6 detector improvement or to close Phase 5. No Phase 6 work should begin on the strength of these exploratory results.
